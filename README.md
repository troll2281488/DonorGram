# DonorGram Nova

Новый самостоятельный интерфейс мессенджера, вдохновлённый перечнем возможностей исходного DonorGram, но с другой компоновкой и визуальным языком. Это **стартовый проект**, а не готовый production-мессенджер.

## Что уже есть

- Адаптивный тёмный интерфейс для телефона, планшета и компьютера.
- Демо-чаты, поиск чатов, текстовые сообщения, быстрые копирование/ответ.
- Регистрация и вход через Firebase Authentication (email + пароль).
- Базовый каркас Firestore для групп и текстовых сообщений.
- DonAI-панель с безопасной заглушкой: ключ модели нельзя класть во фронтенд.
- Геопозиция по явному нажатию, с разрешением браузера; координаты не отправляются автоматически.
- Заготовка интерфейса звонков с объяснением WebRTC/TURN.
- Настройка компактного вида и экономный подход к трафику.
- Пример ограничительных Firestore Rules.

## Важно — чего проект пока НЕ делает

1. В демо-режиме сообщения не синхронизируются между устройствами. Реальная синхронизация возможна только после настройки Firebase и создания комнат через приложение.
2. Создание групп пока не приглашает других пользователей. Не разрешай менять `members` с клиента, пока не добавишь серверную функцию приглашения с проверкой прав.
3. ИИ — только локальная заглушка. Подключай модель через Cloud Functions/Cloud Run, с авторизацией, лимитами, проверкой ввода и бюджетом.
4. Звонки не работают до реализации сигналинга WebRTC, STUN/TURN, входящих вызовов и управления состояниями звонка.
5. Нет end-to-end шифрования, доставки push-уведомлений, антиспама, модерации, блокировок, восстановления аккаунта и тестов нагрузки. Не называй приложение полностью защищённым до независимой проверки.

## Требования

- Node.js 20+ (рекомендуется актуальный LTS)
- Firebase project

## Запуск локально

```bash
npm install
cp .env.example .env
# заполни .env значениями Firebase Web App
npm run dev
```

Открой адрес, который напечатает Vite.

Для production-сборки:

```bash
npm run build
npm run preview
```

## Настройка Firebase

1. Создай проект в Firebase Console.
2. Добавь Web App и скопируй конфигурацию в `.env`.
3. В Authentication включи Email/Password.
4. Создай Firestore Database.
5. Опубликуй правила из `firestore.rules`.
6. Проверь вход/регистрацию и сообщения двумя тестовыми аккаунтами после реализации безопасного механизма создания комнаты с обоими участниками.

`VITE_*` настройки доступны браузеру. Это нормально для Firebase Web App config, но **никогда не помещай** приватный service-account JSON или секретный ключ AI в `.env` фронтенда.

## Рекомендуемая архитектура для настоящего сервиса

- **Клиент:** React + TypeScript (этот проект).
- **Аутентификация:** Firebase Authentication.
- **Текстовые сообщения и метаданные:** Cloud Firestore, запросы с ограничением истории (`limit`) и пагинацией.
- **Файлы:** Cloud Storage; проверять MIME/размер, использовать лимиты и правила доступа. Не загружать медиа автоматически.
- **ИИ:** Firebase Callable Cloud Function или Cloud Run; авторизация, App Check, rate limit, квоты, журналирование без секретов. См. https://firebase.google.com/docs/functions/callable
- **Звонки:** WebRTC + signaling (Firestore/Realtime Database) + STUN/TURN. Не хранить историю ICE-кандидатов бессрочно.
- **Push:** Firebase Cloud Messaging, отдельно реализовать сервис-воркер и согласие пользователя.
- **Защита:** строгие Security Rules, App Check, ограничение частоты, отчёты/блокировки, резервное копирование и мониторинг.

## Экономия трафика

- Текстовые сообщения по умолчанию; медиа только по нажатию.
- Подписка ограничена 100 последними сообщениями в комнате; для длинной истории нужна пагинация.
- Не отправляй координаты в фоне. Добавь временный доступ с явным сроком истечения.
- Для аудио/видео реализуй адаптивный битрейт и кнопку отключения камеры.
- Не делай бесконечные слушатели по всем чатам; загружай только список чатов и активную комнату.

## Перед запуском для многих пользователей

- Напиши и запусти тесты Firestore Rules через Firebase Emulator Suite.
- Добавь e2e-тесты регистрации, доставки, повторной отправки и гонок сети.
- Настрой мониторинг ошибок, лимиты расходов и предупреждения бюджета.
- Проведи аудит безопасности и приватности; проверь требования законодательства для целевых стран.
- Пройди тестирование на iOS Safari, Android Chrome и desktop.
- Убедись, что данные участников не раскрываются посторонним и нет широких правил вида `allow read, write: if true`.
